# aaronpowell.github.io

The source for [aaron-powell.com](https://www.aaron-powell.com), Aaron Powell's personal site, blog, speaking history, and searchable demos.

The site is built with [Hugo](https://gohugo.io/) and deployed to Azure Static Web Apps through GitHub Actions. The repository also contains the supporting search UI, search index builder, and API used by the deployed site.

## Repository layout

| Path | Purpose |
| --- | --- |
| `src/` | Hugo site source, including content, layouts, theme, and static assets |
| `src/content/posts/` | Blog posts |
| `src/content/talks/` | Speaking sessions and talk pages |
| `src/content/demos/` | Interactive demos and experiments |
| `api/` | Supporting API |
| `Search/` | Search UI and index builder |
| `scripts/` | Build-time utilities, including image compression |
| `deploy/` | Azure infrastructure as code |
| `.github/workflows/` | Preview and production build/deploy workflows |

## Prerequisites

- [Hugo Extended](https://gohugo.io/installation/) (the workflows use the latest release)
- [Node.js](https://nodejs.org/) 20 or newer
- npm

The local PowerShell helper scripts expect a Hugo executable named `hugo.exe` in the repository root. Alternatively, use the `hugo` command directly from your `PATH`.

## Run locally

Install the JavaScript dependencies used by the build scripts:

```powershell
npm ci
```

Start Hugo with drafts and future-dated content enabled:

```powershell
.\run.ps1
```

Then open <http://localhost:4014>. To run Hugo without the helper script:

```powershell
hugo server --source .\src --destination .\.output --port 4014 --bind 127.0.0.1 --buildDrafts --buildFuture
```

Build a production-like output:

```powershell
.\hugo.exe --source .\src --destination .\.output --config config.toml,config.speaking.toml --minify
node .\scripts\compress-images.js --input .\.output
```

The generated site is written to `.output/`, which is not committed.

## Create content

Use the helper scripts to create content with the expected filename and front matter:

```powershell
.\New-Post.ps1 -Title "My new post"
```

```bash
./new-post.sh "My new post"
./new-talk.sh "My new talk"
```

Posts are created under `src/content/posts/` and talks under `src/content/talks/`. The post helper also creates a matching image directory under `src/static/images/`.

## Build the supporting applications

The deployment workflow builds the supporting applications in addition to Hugo:

```powershell
Push-Location .\api
npm ci
npm run build
Pop-Location

dotnet build .\Search\Search.sln --configuration Release
```

The search index builder consumes the JSON generated by Hugo:

```powershell
dotnet run --project .\Search\Search.IndexBuilder -- .\.output\index.json
```

## Deployment

- Pull requests targeting `main` build a preview deployment through [`pr.yml`](.github/workflows/pr.yml).
- Pushes to `main`, scheduled dispatches, and manual runs deploy production through [`main.yml`](.github/workflows/main.yml).
- The reusable workflow in [`build-and-deploy.yml`](.github/workflows/build-and-deploy.yml) builds the Hugo site, API, search UI, and search index, provisions Azure resources with Bicep, and deploys the combined output to Azure Static Web Apps.
- Closing a pull request removes its preview deployment through [`pr-close.yml`](.github/workflows/pr-close.yml).

Production deployment requires the Azure and Static Web Apps secrets configured in the repository environments. Local builds do not require those secrets.

## Making changes

1. Create a branch from `main`.
2. Make the change and run the relevant local build or preview.
3. Open a pull request against `main`.
4. Review the generated preview before merging.

Content and theme changes usually belong in `src/`. Changes to the deployed infrastructure belong in `deploy/`; avoid editing generated output in `.output/`.
